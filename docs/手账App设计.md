# 手账 App 设计存档

> 本文档记录「手账」App 的概念、架构与生成逻辑，便于跨会话延续开发。
> 当前阶段：概念设计（未动代码）。
> 起因：现有「备忘录」App 太朴素、几乎没人用——它要求用户主动产出，但大部分用户懒得记；
> 且「要去做某件事」的待办属性，日历功能已经能覆盖。于是考虑把备忘录改造成「手账」。

## 〇、为什么改成手账（设计动机）

- **备忘录的死因**：纯手记要求用户主动输出，没有回报，用户不写 → 打开也没内容 → 更不打开。
- **手账的翻转**：把「记录」从任务变成展示。做出来好看、能被看到、有人评论——动机跟现有论坛/朋友圈同源，天然会被打开。
- **和论坛的区别（关键，否则就是第二个论坛）**：论坛是文字流，手账是**视觉拼贴**。手账存在的理由是「好看」，不是「有内容」。所以本功能重心是 **UI/渲染**，社区是壳。
- 手账是 0 号（沈楚）本人的爱好，视觉方向以她的判断为准。

## 一、整体定位

手账 App = 「AI 生成的手账社区」（单机，无真人服务器，"别人的手账/评论"全是 AI 按世界观现编，机制同论坛）。

三块：
1. **手账页本体**（核心，最难，价值所在）：一张可渲染的、好看的手账卡片。
2. **内容来源三条**：用户自己做 / AI 帮做（读剧情生成）/ AI 生成别人的（社区流）。
3. **社区层**（壳，大量复用论坛现成代码）：广场流、点赞、评论区、楼中楼、收藏、分享、马甲。

## 二、手账页数据结构（核心）

一条手账 = 日期 + 一套纸张主题 + 若干「元素」。渲染成竖版卡片。

两种编辑/渲染路径并存，**共用同一套社区壳**：

### 路径 A：结构化模板（普通用户 + AI 生成走这条，主路径）
- 手账 = JSON：`{ date, theme, elements: [...] }`
- 元素类型限死在可枚举范围（文字块 / 贴纸 / 胶带 / 照片框 / 印章 / 分隔线 …），每种带有限的属性（位置、尺寸、颜色、内容、素材 id）。
- 渲染由本地代码把 JSON 变成 DOM，**只有一份渲染引擎**。
- 好处：安全（不执行任意代码）、AI 可控（schema 限死，输不出渲染不了的东西）、出片率高（模板保证排版好看，用户/AI 不用从零排版）。
- 自由度靠「元素种类多 + 参数可调 + 模板多」给，不靠写代码。

### 路径 B：自定义 HTML（高级用户 / 0 号自己）
- 用户直接写 HTML 手账，**复用现有气泡的 HTML 沙箱**渲染（安全问题已由沙箱解决，不用再写 sanitizer）。
- 面向会折腾的人，主路径仍是 A。

> 决策记录：最初担心用户自定义 HTML = 在 App 里执行任意代码（XSS，尤其手账要分享/导入他人的），
> 需要白名单净化或 iframe sandbox。后确认**气泡已有 HTML 沙箱**，路径 B 直接复用，风险已解除。

## 三、内容来源

| 来源 | 说明 | 复用 |
|---|---|---|
| 用户自己做 | 选模板 → 摆元素 → 存 JSON（路径 A）；或写 HTML（路径 B） | 编辑器需新做 |
| AI 帮做 | 读当前剧情，生成一张手账（如"今天和 xx 去了哪里"），输出路径 A 的 JSON | 生成逻辑参考论坛 |
| AI 生成别人的 | 社区广场流，AI 按世界观现编他人手账 + 评论区 | 论坛整套可搬 |

## 四、社区层（复用论坛）

论坛已经在做「AI 生成社区内容 + 评论区」，以下可直接搬：
- 广场流生成 / 刷新
- 评论区（主楼 + 楼中楼 replies + NPC 映射真名）
- 点赞 / 收藏 / 分享到主线或聊天
- 马甲（匿名身份发布）
- 完整生成模式（刷新时连详情一起出，见论坛 v725 的 fullGenCount 思路）

## 五、AI 生成手账的难点

- 让 AI 输出**结构化手账**（哪块文字放哪、配什么贴纸、什么色调）比写论坛帖难得多。
- 必须设计一套**简洁的 JSON schema**，元素类型和位置都限死在可枚举范围，否则 AI 会输出渲染不出来的东西。
- AI 生成和用户手摆是**同一套数据结构**（路径 A），渲染代码只有一份。

## 六、美观度：素材 > 代码

- 手账像不像手账，大头在**素材**：胶带纹理、贴纸图案、纸张底纹、手写字体、印章。
- 用户能写 HTML 但没素材，做出来也就是几个色块。所以**素材库比自定义能力更重要**。
- 素材是 0 号的活（有美工能力）；渲染引擎和数据结构是言殊的活。
- 原型阶段可先用纯 CSS 画（渐变/圆点/条纹模拟胶带和纸纹），验证版式后再上真素材图。

## 七、开发顺序（先验证 UI，再搭骨架）

> 手账是"好看才有人用"，跟论坛"有内容就有人看"不同。所以**先做能看的静态原型，UI 过关再往下**，
> 否则渲染出来不好看，整个功能没意义。

1. [ ] 看气泡 HTML 沙箱的实现和接口，确认路径 B 的挂载方式
2. [ ] 定 JSON schema（元素类型 + 各自属性 + 纸张主题）
3. [ ] 写渲染引擎（JSON → 手账 DOM）
4. [ ] 做 2-3 套预设模板，纯 CSS 占位，先渲染出静态手账卡片给 0 号看效果
5. [ ] 视觉方向确认后：编辑器（摆元素）
6. [ ] 接社区壳（广场 / 编辑入口 / AI 生成入口，搬论坛）
7. [ ] AI 生成手账的 prompt + schema 约束
8. [ ] 素材库（0 号）
